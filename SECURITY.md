# Security Policy

## Supported Versions

| Version | Supported |
|---|---|
| `0.1.x` (current / active development) | Yes |

## Reporting a Vulnerability

If you discover a security vulnerability in Personal AI Workspace, please report it privately:

1. **Do not open a public issue.**
2. Send an email to the repository owner or submit a private security advisory via GitHub.
3. Include detailed steps to reproduce, potential impact, and your environment.

We aim to acknowledge reports within 48 hours and provide a fix or mitigation plan within 7 days.

## Security Principles & Threat Model

Personal AI Workspace is designed for self-hosting on local networks, private servers, and Tailscale overlays:

1. **Principle of Least Privilege**:
   - The AI agent or execution sandbox **NEVER** receives root privileges, `/var/run/docker.sock`, access to the host home directory (`~`), or access to `.env` secrets.
   - Execution occurs in isolated containers with strict CPU, RAM, and PID quotas, and read-only root filesystems where applicable.

2. **Network Isolation**:
   - Docker container ports for internal services (e.g. Open WebUI, internal databases) are bound to `127.0.0.1` by default.
   - Remote access should be routed through Tailscale Serve / Tailscale Funnel or a hardened HTTPS reverse proxy (e.g. Caddy, Traefik, Nginx) with valid SSL/TLS certificates.

3. **No Dynamic Execution in Authenticated Origin**:
   - Generative UI components produced by OpenUI execute against a whitelist of verified React components.
   - Any raw HTML or external code artifacts generated by AI are rendered inside sandboxed `<iframe>` tags with `sandbox="allow-scripts"` and **without** `allow-same-origin`, preventing access to session cookies, JWTs, or local storage.

4. **Secret Management**:
   - No plaintext secrets or API keys are returned to client browsers or mobile devices.
   - All external model API calls and cloud provider keys remain strictly server-side.
   - Secrets are configured via `.env` (permissions `0600`) or Docker secrets, and `.env` is strictly excluded in `.gitignore`.

5. **Input & File Sanitization**:
   - File uploads are validated for MIME type integrity, SHA-256 hashed, and checked against zip-bomb and path-traversal attacks (`../`).
   - Server-Side Request Forgery (SSRF) protections guard against agents probing RFC 1918 internal networks.
